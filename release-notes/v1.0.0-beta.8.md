# Ogoune v1.0.0-beta.8

Nothing new to use. This release is about what an upgrade can be trusted to do, and writing that down — the groundwork for leaving beta.

## What an operator gets

**Two pages that say what you can rely on.**

- [Upgrading](https://docs.ogoune.com/self-host/upgrading) — back up, upgrade the server then the agent (either order works), what is guaranteed, how to roll back, and one note per version back to the beta.5 security fix.
- [Compatibility](https://docs.ogoune.com/self-host/compatibility) — what semantic versioning covers here (the v1 API, the agent wire protocol, agent and server configuration, the database as an upgrade path, supported platforms) and what it does not (the internal `/api/`, the database schema itself, log formats). Before 1.0.0 these are already treated as covered; a beta that has to break one will say **Breaking** in the first line of its notes.

**Upgrades are tested against real databases.** Every build now restores a database written by an earlier release — v1.0.0-beta.4 and v1.0.0-beta.7, on SQLite and on PostgreSQL — runs its migrations, and fails unless every table survives with the same rows, byte-for-byte on the columns that existed before. A migration that rewrote or dropped your data would not get past CI.

**Rich text renders more strictly.** Incident updates and the public status timeline accepted a bare `<input>` element in their HTML, needed for task-list checkboxes. They now accept it only as a read-only checkbox; any other kind of input is dropped. There is no known way this was abused — no form or field names were ever allowed — but a public status page should not render form fields at all.

## Upgrading

No migration to run, nothing to configure. The agent is unchanged since beta.7.

## What contributors get

- `make sonar` runs the SonarQube gate locally, versioned by release so "new code" means the release delta; generated sqlc code and test doubles are excluded from the measure. First full pass: no vulnerabilities, no security hotspots left to review.
- The most complex functions in the repository, monitoring, incident and authentication code are split up, with no behaviour change; every function that scored 40 or more is now under it.
- A default `DATABASE_URL` carrying a password, left in the configuration code from another project and reachable only from a test, is removed.
- Adding a release to the upgrade gate is a documented procedure (`internal/database/upgrade/testdata/README.md`).
