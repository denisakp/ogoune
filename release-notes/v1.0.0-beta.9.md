# Ogoune v1.0.0-beta.9

Privacy tools: see, download and erase the personal data an install holds — and two sign-in defects fixed along the way.

## What an operator gets

**See and download what the install holds about you.** Settings → Privacy lists every category of personal data held about the signed-in user — account, sessions (revoked ones included), API keys, incident updates you posted, notification channels whose configuration contains your address, report recipient and reports sent — with counts and links to where each is managed, and the categories that are not personal data. **Download my data** returns it all as one JSON file after re-entering your password (and two-factor code when it is on), every time. The file holds no secret in usable form. A channel configuration that cannot be decrypted is reported as "could not be checked", never skipped. See [Privacy & your data](https://docs.ogoune.com/guide/privacy).

**Erase a person's data on request.** Settings → Privacy → *Erase someone's data* serves the two requests an operator actually receives:

- an **address that never had an account** — a former colleague still on an email channel, the monthly report recipient;
- a **former account** — accounts pile up on their own when `AUTH_EMAIL` or a profile email changes.

A preview lists what will be removed, what is kept (incident updates stay published, without an author) and what needs a manual review (configurations that cannot be decrypted, addresses inside URLs). Confirming takes the address typed again plus your password and two-factor code. The erasure is all or nothing; a channel edited at the same moment stops it and nothing changes. Each erasure leaves a record with a keyed fingerprint of the address — never the address — so a later preview can say "erased on …". Your own account cannot be erased here.

**Notification channels can be disabled.** A channel an erasure leaves with no recipient is disabled, not deleted: it sends nothing — alerts, reminders, escalations, reports, tests — and counts no failures. The channel list says why; add a recipient, then **Enable** it (`POST /api/v1/notification-channels/{id}/enable`). A monitor whose only linked channels are disabled falls back to its component's or the default channels. When the erasure disables the channel monthly reports and escalation digests are sent through, the preview says which one takes over. The monthly report recipient, when erased, is cleared and reports are switched off until you set a new one.

## Fixed

- **A mistyped current password no longer signs you out.** Changing or resetting your password, or turning off two-factor, with a wrong current password signed you out mid-typo. It is now a validation error next to the field.
- **Two-factor backup codes now work.** The 10 codes shown at two-factor setup were never saved, so none was ever accepted. They are now stored as hashes and each is accepted once in place of the authenticator code, at sign-in and when re-entering your password. **Codes from a setup made before this release do not work: set up two-factor again to get a new set.**

## Upgrading

One migration, additive (`0037`): channels gain a disabled state, erasures a record table. Existing channels stay enabled; nothing to configure. The agent is unchanged since beta.7.

> **Do not downgrade below beta.9 after an erasure.** Earlier versions do not know about disabled channels and would send to them again. Restore the pre-upgrade backup instead.

Every build is now also tested by upgrading a database written by beta.8, on SQLite and PostgreSQL — the first fixture to cross a real migration.

## What contributors get

- The search palette no longer ships `fuse.js`; its local fallback is a plain ranked match.
- The OpenAPI contract documents the privacy endpoints under `/me/privacy` (they were listed under a doubled `/v1` prefix).
- New code passes the Sonar gate with no violations.
